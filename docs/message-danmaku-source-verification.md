## 2026-10-31 实际通知来源核验

在通知增强版1.2.0.3运行、用户已开启弹幕且授权允许时，从设置页读取到：系统通知20条，已识别QQ/TIM/微信0条，新消息0条。

为排除严格应用名称匹配漏识别，使用Windows提供的Invoke-CommandInDesktopPackage调试入口，在已安装应用身份下执行一次元数据诊断。仅调用一次GetNotificationsAsync，不申请权限，不读取任何通知标题或正文；仅统计AppInfo显示名、应用标识和数量。结果Access=Allowed、Count=20，20条均来自其他应用，没有QQ、TIM或微信来源。因此本次不是来源名称别名匹配问题。

诊断工具及结果保留在忽略目录work/notification-metadata-probe与artifacts/danmaku-light/notification-source-metadata.json，不随源码发布。此调试命令的隐私行为由系统控制，结果只能用于本机故障调查，不作为生产接入架构。

结论：当前TIM3.4.8.22138的消息尚未进入所检查的Windows通知池。轻量通知转显通道不能从没有提供的数据中恢复聊天内容；事件读取修正只消除了持续查询的干扰，不等于实现TIM消息接入。测试弹幕正常已证明显示链路可用。

后续需选择真实消息来源。可选QQ账号桥接候选NapCatQQ，其官方Windows Shell文档要求QQ环境及用户登录，不能声称可直接接入经典TIM3.4.8。若采用，需用户另行授权额外组件安装并自行登录；同账号与TIM的同时在线和真实群私聊投递需实机验证。未安装或运行该第三方组件，不将其列为已支持。https://doc.napneko.icu/guide/boot/Shell
