# Windows系统通知弹幕实施记录

日期：2026-10-31。对应用户批准执行的 `docs/superpowers/plans/2026-10-31-windows-notification-danmaku.md`。

## 已完成

- 来源从QQ/TIM/微信名称匹配改为任意Windows通知应用的AppUserModelId。元数据列表动态更新，显示应用名，标识用于区分同名来源。仅在应用获得允许后解析正文。
- 提供逐应用选择和“接收所有应用”开关。旧JSON可加载，旧聊天软件开关不会自动扩展到所有应用；SchemaVersion仍为1。
- 显示时机：始终、仅全屏、仅非全屏。禁显期间不积压，在途读取跨越显示许可边界时丢弃；不在退出全屏后补发旧通知。
- 全屏时可跟随前台显示器，退出后返回保存的显示器。桌面和任务栏不认作全屏应用；不识别具体游戏/视频进程名，不判断独占渲染。只在前台上下文变化时重新置顶，保持鼠标穿透与不激活。
- 设置页应用列表和显示时机使用现有主题控件；原字体、颜色、透明度、区域、纵向/横向、关键词及快捷键继续使用。轮盘入口显示“通知弹幕”。
- 保留事件驱动读取、旧通知基线、截图/锁屏/字幕暂停和错误停止重试。不开启高速通知枚举，不修改Windows免打扰，不删除用户通知中心记录。

## 实施决定

Ruling: 来源列表采用观察到的通知应用和已保存选择，不将所有已安装应用宣称为支持 — 只有系统通知池中出现的来源才能证明该接口提供数据 — 代价是新应用第一次通知可能需要先用于发现，再由用户勾选；也可明确开启所有来源。

Ruling: 默认来源为空，不自动继承为全部应用 — 旧设置可能已开启QQ/TIM弹幕，不能在更新后意外展示其他应用隐私通知 — 代价是更新后需要明确勾选来源或接收所有应用。

Ruling: 全屏按前台窗口覆盖显示器判断，不尝试注入游戏 — 实现无边框全屏显示与不抢焦点的普通桌面窗口 — 代价是独占全屏、受保护画面和特定游戏置顶策略不保证显示，必须手工验证。

## 真实通知端到端

使用系统调试入口在已授权包身份中运行独立验证程序，只允许测试应用自身来源。先建立旧通知基线，再发送一条明确标记为本地测试的Windows Toast，使用最终生产来源及运行时驱动弹幕窗口。

结果：`NotificationPermission=Allowed`、`Presentations=1`、`OverlayVisible=true`；所选来源1条、本次新通知1条。验证后移除本次测试通知，不修改其他通知。工具和计数结果位于忽略目录 `work/windows-notification-e2e`、`artifacts/danmaku-light/windows-notification-e2e.json`；没有存储其他应用正文。

这证明真实Windows通知进入弹幕链路，不是直接调用测试弹幕。没有在实际游戏、真实播放器全屏、Windows11或混合DPI切换上完成手工验收；不能据此宣称所有全屏场景均兼容。TIM3.4.8自带提醒仍不是本模块的数据来源。

## 交付与使用

通知增强包版本1.2.0.4，沿用原本地签名证书，不新增证书信任。准备延迟更新，不强制关闭用户进程。不推送GitHub或发布公开Release。

退出旧版后，从已安装通知增强版入口重新打开；设置→消息弹幕→允许通知访问→启用并应用。列表出现来源后勾选目标应用，或开启接收所有应用，再选择显示时机并应用。历史通知只作基线，不重播；使用后续新通知验证。

便携可执行文件仍可预览；真实通知读取需要已安装通知增强版的包身份。系统通知访问已授权不代表所有客户端均产生系统通知。
