# 实时视频字幕翻译与透明字幕浮层设计

日期：2026-10-27

状态：已批准（2026-10-27）

## 目标

用户框选视频字幕区域后，月语悬浮球持续在本地检测画面变化并 OCR，只把变化后的字幕文字发送给当前翻译服务。译文以无背景文字显示在字幕区域上方或下方，字号可调，并尽量跟随字幕变化。

用户已经确认以下显示规则：

- 新字幕正在 OCR 或翻译时，继续显示上一条有效译文。
- 新译文第一次出现非空文字时，立即用新译文替换旧译文。
- 替换必须原子完成，不能出现新旧译文重叠或可感知的空白闪烁。
- 第一阶段使用普通完整翻译结果；“首字流式显示”作为第二阶段，不在本次实现范围。

## 为什么要改

现有字幕翻译已经具备固定区域截图、本地画面差分、Windows OCR、文字去重、翻译缓存和无激活浮层，但实际链路是串行的：

1. 截图并检测变化。
2. 等待 120 ms 稳定延迟。
3. 再次截图并 OCR。
4. 等待网络翻译。
5. 更新完整翻译卡片。
6. 再等待至少 300 ms 后才进行下一轮采样。

因此，网络翻译期间不会继续检测下一句字幕；旧字幕的 OCR 或翻译也不能被新字幕及时取代。显示层目前是带背景、标题、原文、状态和控制栏的完整玻璃卡片，而不是贴合视频字幕区域的纯文字。

## 范围

### 本阶段包含

- 低延迟的“最新字幕优先”采样、OCR 和翻译流水线。
- 新字幕出现时取消或忽略旧字幕的过期 OCR、翻译结果。
- 上一条译文保持显示，直到新译文成功返回。
- 新译文首次非空时原子替换旧译文。
- 专用透明字幕显示模式，不显示常态背景、标题、原文或状态卡片。
- 字幕位置支持“上方 / 下方 / 自动选择”并在设置中持久化。
- 继续支持现有字幕字号设置，并改善设置说明。
- 保持 Windows 10 22H2 x64、Windows 11 x64、多显示器及混合 DPI 兼容。
- 保持现有隐私约束：截图不上传，只发送 OCR 文字；不保存翻译历史。

### 本阶段不包含

- 流式翻译协议和逐字追加显示。
- 读取播放器内部字幕轨、网页字幕 DOM 或 DRM 字幕。
- 云端 OCR。
- 自动识别视频画面中不断移动的字幕区域。
- 独占全屏游戏覆盖层支持；无边框全屏和普通窗口播放器是主要目标。
- 翻译历史、导出或保存字幕。

### 失败条件

- 新字幕到来后仍等待旧翻译完成，导致显示落后一句以上。
- 旧翻译晚到后覆盖新字幕译文。
- 新译文替换旧译文时出现两段文字叠加、空白帧或明显闪烁。
- 无字幕期间因为 OCR 空结果或临时网络错误清空最后一条有效译文。
- 透明字幕层遮挡或再次捕获框选区域，造成 OCR 自反馈。
- 混合 DPI 下字幕文字偏离框选区域或跑出显示器工作区。

## 现有组件

- `SubtitleTranslationController`：当前串行采样、OCR、翻译和重试循环。
- `TranslationRuntime`：字幕会话、区域选择、暂停、捕获互斥和翻译服务生命周期。
- `TranslationOverlayWindow`：当前完整翻译卡片和字幕操作栏。
- `WindowsScreenOcrService`：单 STA worker 上串行执行 Windows OCR。
- `TranslationRegionCaptureService`：固定区域截图，不隐藏普通窗口。
- `TranslationOverlayPlacementPolicy`：现有“避开捕获区域”的放置策略。
- `TranslationCenter`：翻译去重、并发限制、限速和 10 分钟内存缓存。
- `TranslationSettings`：保存区域、采样间隔、透明度、字号和旧浮层位置。

## 方案比较

### 方案 A：仅压缩现有串行循环

降低采样间隔、减少稳定等待并复用 OCR 引擎。

优点：改动小，回归风险低。

缺点：OCR 和网络翻译仍互相阻塞；一句字幕翻译较慢时，下一句字幕无法及时进入处理；很难稳定达到实时观感。此方案单独采用不足以满足目标。

### 方案 B：最新字幕优先三级流水线 + 专用透明字幕层

采样、OCR 和翻译分开运行；每个阶段只处理最新有效字幕；任何新字幕都使旧字幕的后续结果失效。显示层始终保留最后一条成功译文，直到新译文首字到达。

优点：延迟不在阶段之间累加；旧请求不会阻塞新字幕；与现有 OCR、翻译和浮层基础兼容；可以继续支持所有现有翻译服务。

缺点：需要重构字幕控制器的并发模型，并新增专用显示状态、设置和多 DPI 定位测试。网络服务本身的首包延迟仍不可控。

采用：**方案 B**。

### 方案 C：方案 B 加流式翻译

为支持流式输出的 OpenAI 兼容接口增加逐字结果。新译文第一个 token 到达时替换旧译文，后续 token 继续追加。

优点：感知延迟最低。

缺点：需要扩展翻译协议、取消语义和 UI 增量更新；免费和其他传统服务仍需回退到完整结果。

决定：保留为第二阶段，不进入本次实现或验收条件。

## 用户可感知行为

### 开始

用户从快捷键或轮盘启动字幕翻译并框选区域后：

- 旧会话和旧译文立即清除。
- 显示透明字幕层，但在第一份译文返回前不显示上一视频留下的内容。
- 字幕层不显示常态卡片背景或标题。

### 等待新译文

检测到新字幕后：

- 画面继续显示最后一条成功译文。
- “正在翻译”或 OCR 状态不得覆盖该译文。
- 网络错误、超时、空 OCR、临时无文字都不清除最后一条成功译文。

### 新译文到达

当当前字幕代次收到第一个非空译文时：

- 在同一个 WPF Dispatcher 回调中清空旧文字并设置新文字。
- WPF 只提交一帧最终结果，用户不能观察到中间空白。
- 不执行旧译文向新译文的淡入淡出或交叉混合。
- 如果新译文与当前显示文字相同或近似相同，则保持现状，避免无意义刷新。

### 字幕消失或画面静止

没有识别到文字时继续保留最后一条译文，不因空帧清空。字幕会话结束、重新选区、应用关闭或用户明确停止时才清除。

### 失败和重试

- 网络、超时、额度等临时失败：保留最后译文，按有上限的退避策略重试当前字幕。
- 认证失败、语言不支持、OCR 语言包缺失：保留最后译文，暂停自动重试并记录和展示非阻塞错误。
- 更新字幕一旦出现，立即取代旧字幕的重试。
- 可操作的认证、语言包和定位错误使用透明字幕层中的临时单行提示，并在相同时间显示托盘通知；提示不能替换或清空译文，约 4 秒后自动消失。
- 普通网络失败前两次静默重试，连续失败后才显示一次简短提示，避免每个短字幕都产生警告。

### 暂停、继续、重新选择和停止

- 暂停：停止采样并取消在途 OCR/翻译，保留当前译文。
- 继续：保留当前译文，从最新画面重新采样。
- 重新选择：清空旧译文，选择新区域后启动全新会话。
- 停止：取消所有在途工作并隐藏字幕层、清空最后译文。

## 技术设计

### 设置模型

新增字幕位置枚举：

```csharp
public enum SubtitleAttachmentMode
{
    Auto,
    Above,
    Below
}
```

在 `TranslationSettings` 中新增：

```csharp
public SubtitleAttachmentMode SubtitleAttachment { get; init; } =
    SubtitleAttachmentMode.Auto;
```

规则：

- `Auto`：优先选择字幕层完整放得下且空间更大的一侧。
- `Above`：字幕层底边位于捕获区域顶边上方，保留 8 DIP 间距。
- `Below`：字幕层顶边位于捕获区域底边下方，保留 8 DIP 间距。
- 如果指定一侧空间不足，先尝试另一侧；两侧都不能完整避开捕获区域时，按“放置失败回退”处理。
- 水平中心与捕获区域中心对齐，最大文字宽度不超过捕获区域宽度和工作区可用宽度中的较小值。

继续保留现有 `SubtitleRefreshIntervalMs` JSON 字段，但语义调整为“画面检测采样间隔”。新安装默认值为 150 ms，合法范围扩展为 100–1500 ms；现有 300–1500 ms 配置继续合法并原样保留，不进行静默迁移。

继续使用：

- `SubtitleFontSizeDip`：14–36 DIP。
- `SubtitleOverlayOpacity`：作为文字不透明度，60–100%。
- `SubtitleRegion`：字幕捕获区域。

旧的 `SubtitleOverlayPlacement` 字段保留以兼容现有设置文件，但新的区域锚定字幕模式忽略自由拖动位置。不得因旧字段存在而放弃上方、下方或自动定位。

### 设置界面

“设置 > 实时翻译 > 字幕翻译”调整为：

- 画面检测间隔：100–1500 ms，并标明 150 ms 适合实时字幕。
- 显示位置：自动、字幕上方、字幕下方。
- 文字不透明度：60–100%。
- 字号：14–36 DIP。
- 说明常态显示为纯文字、无背景，并使用自动阴影/描边保证可读性。

每个新增控件需要有自动化名称。保存、导入、导出、验证和设置合并行为必须覆盖新字段。

### 字幕显示层

继续复用 `TranslationOverlayWindow` 的操作 token、捕获排除和关闭生命周期，不为字幕另建一套无保护的窗口。

新增“紧凑字幕显示状态”：

- `OverlayCard`、标题栏、原文、元数据、复制按钮、状态卡片和常态控制栏不显示。
- 根背景和窗口背景完全透明。
- 只显示译文 `TextBlock`，透明背景，文字带柔和阴影或等效描边。
- 不改变颜色主题以适配视频；浅色背景场景使用深色字形配浅色光晕，深色背景下使用白色字形配深色阴影。主题跟随现有系统资源。
- 文本居中对齐、自动换行、宽度受捕获区域限制。
- 首次显示可做一次不超过 80 ms 的轻微淡入；新旧译文之间禁止淡入淡出。
- 高对比模式或系统关闭动画时禁用字体阴影/过渡，优先可读性。

控制入口：

- 常态只显示译文，不显示背景卡片。
- 紧凑字幕模式使用点击穿透窗口，避免字幕文字挡住视频或播放器的鼠标操作。
- 托盘菜单新增“字幕翻译”子菜单，在字幕会话运行时提供暂停/继续、重新选择和停止。
- 现有字幕快捷键和轮盘动作继续负责启动/停止；重新选区可以通过托盘命令或停止后重新启动完成。
- 进入交互翻译卡片模式前移除点击穿透样式，字幕模式关闭后恢复普通浮层行为。

### 放置算法

在 `FloatDesk.Core` 新增纯几何策略，例如：

```csharp
public static PixelRect? PlaceAnchored(
    PixelRect captureRegion,
    PixelSize overlaySize,
    PixelRect workArea,
    SubtitleAttachmentMode mode,
    int gap = 8)
```

要求：

- 所有计算使用物理像素，进入 WPF 布局前显式进行 DPI 换算。
- 先根据工作区限制字幕最大宽度，再测量文本高度，最后计算锚点。
- 上方/下方候选必须完整位于工作区内且不与捕获区域相交。
- 自动模式检查两侧可用高度；选择能完整容纳字幕且剩余空间更大的一侧。
- 放置失败回退：
  - 如果捕获排除已确认生效，可选择空间更大的一侧放置，允许在大字幕或极端区域下覆盖捕获区域；捕获排除负责避免 OCR 自反馈，并显示一次简短警告。
  - 如果捕获排除不可用，暂停采样但继续显示最后译文，把字幕层钳制在空间更大的一侧，并提示用户重新选择字幕区域；恢复前必须重新定位。
  - 如果字幕层连显示器工作区都放不下，钳制到工作区并暂停采样，不能无限扩张。
- 文本换行导致高度变化后必须重新定位，不能沿用旧窗口高度。
- 显示器移除、DPI 改变、字幕区域重新选择时重新解析显示器和区域。

现有 `TranslationOverlayPlacementPolicy.PlaceOutside` 可保留给交互翻译卡片；字幕模式使用新的锚定策略。

### 最新字幕优先流水线

`SubtitleTranslationController` 重构为三个逻辑阶段，不要求新建三个长期线程；可使用任务、取消令牌和“单槽最新值”协调。

#### 1. 采样循环

- 以 `SubtitleRefreshIntervalMs` 持续采样捕获区域。
- 使用现有 `SubtitleFrameChangeDetector` 做低成本变化检测。
- 发现变化后等待 80–100 ms 再采样一次稳定帧。
- 如果稳定帧仍在剧烈变化，最多再等待一个短周期，然后提交当前帧，避免无限等待。
- 每次提交稳定帧都获得新代次号；代次从 1 开始递增，溢出后回到 1。
- 采样循环不等待 OCR 或翻译完成。

#### 2. 最新 OCR

- 只保留一个正在执行的 OCR 和一个待处理的最新帧槽。
- 新帧到来时取消旧 OCR 调用；如果底层 WinRT OCR 已经开始且不能中断，允许它完成但忽略结果，然后只识别最新槽。
- OCR 结果返回后检查会话、暂停状态和代次；过期结果直接丢弃。
- OCR 文本使用现有 `TranslationTextProcessor.Normalize`。
- OCR 文本为空、`OcrNoText` 或错误时不清空已显示译文。
- 稳定帧得到明确的 `OcrNoText` 或空文本时，推进字幕代次并取消上一条字幕尚未完成的翻译和重试，防止字幕已经消失后迟到译文突然出现；最后显示的译文仍保留。
- OCR 失败属于暂时错误时，不推进字幕代次，也不取消上一条字幕的重试，避免一次识别波动丢掉有效字幕。
- 与最后一个成功或正在翻译的源文字近似重复时，不重新翻译，避免画面轻微变化造成重复请求。

#### 3. 最新翻译

- 新源字幕取代旧字幕时，取消旧字幕的在途翻译。
- 同一字幕只允许一个翻译请求。
- `TranslationCenter` 的缓存、并发限制和限速继续生效。
- 结果返回后检查会话、暂停状态和字幕代次。
- 成功结果进入显示提交；取消、失败和过期结果绝不覆盖显示。
- `NoTranslationNeeded` 视为成功透传，用规范化后的源字幕替换旧译文。
- 网络类失败对当前字幕使用短退避重试；新字幕出现即取消旧重试。

#### 4. 显示提交

新增路由能力，例如：

```csharp
void ShowSubtitleText(
    TranslationRouteHandle operation,
    string translatedText);
```

`TranslationOverlayWindow` 只接受当前操作 token 的更新：

```csharp
if (!IsCurrentOperation(operation) || string.IsNullOrWhiteSpace(text))
    return;

TranslatedTextBlock.Text = "";
TranslatedTextBlock.Text = text;
PositionSubtitleWindow();
```

清空和赋值必须在同一个 Dispatcher 回调中完成。第一阶段不显示未完成的流式片段。

### 并发状态

会话状态至少包括：

- `sessionGeneration`
- `captionGeneration`
- `paused`
- `lastSubmittedText`
- `lastDisplayedText`
- OCR 取消令牌
- 翻译取消令牌

规则：

- 锁内只修改字段和快照，不在锁内等待网络或 UI。
- 每个 `await` 后重新检查会话代次、暂停和取消状态。
- 旧代次的扫描、OCR、翻译、重试和 UI 更新全部无效。
- 停止和重新选区必须等待已有会话循环退出后再启动新循环，避免两个采样循环并存。
- 所有取消令牌和帧对象在正常、取消和异常路径中释放。

### 现有接口影响

- `SubtitleTranslationController.StartAsync`、`StopAsync`、`Pause`、`Resume`、`ReselectAsync` 对外行为保持，内部并发模型变更。
- `ITranslationRouteHost` 增加字幕文本更新入口，仍使用 Task 9 的 opaque operation token。
- 全卡片 `ShowResult` 继续服务选中文字和区域 OCR 翻译，不用于紧凑字幕模式。
- `TranslationRuntime` 现有捕获暂停、紧急暂停、会话锁定、设置重载和字幕操作 token 语义保持不变。
- `TrayService` 增加字幕会话状态和暂停/继续、重新选择、停止回调；菜单项只在字幕会话运行时启用。

## 性能目标

在字幕区域较小、OCR 语言包已安装、翻译服务首包正常的前提下：

- 单次截图和差分 CPU 工作应低于 25 ms。
- 稳定等待不超过 100 ms。
- OCR 目标处理时间不超过 300 ms。
- 新译文返回后，UI 在下一帧完成替换。
- 从新字幕稳定到译文出现，响应型服务目标为 0.5–1.2 秒；免费公网服务按 best effort，不承诺固定上限。

流水线必须保证网络翻译慢时仍能检测下一句字幕，而不是等当前请求结束后才继续采样。

## OCR 优化

- 在 `WindowsScreenOcrService` 的单 STA worker 内按语言缓存 `OcrEngine`，语言改变或服务释放时销毁旧引擎。
- 缓存只存在于 OCR worker 线程，避免 WinRT 对象跨线程使用。
- 继续对超大区域进行现有缩放，防止 OCR 前处理阻塞。
- 不改变 OCR 结果格式和错误码，避免影响区域 OCR 翻译。

最后译文只保存在字幕会话内存中；停止、重新选区、设置切换或应用退出时清除。现有翻译缓存继续受会话锁定和 10 分钟过期策略控制。

## 兼容性

- 目标框架保持 `net10.0-windows10.0.19041.0`。
- Windows 10 22H2 x64 与 Windows 11 x64 均使用 Windows.Media.Ocr。
- WPF 透明窗口继续使用 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`。
- 捕获排除继续使用现有 Windows Display Affinity 路径；不支持捕获排除的系统上，放置策略仍必须避免浮层进入捕获区域。
- 混合 DPI、负坐标显示器和显示器热插拔必须通过纯几何测试和 Windows 手工验证。

## 测试策略

### Core

- 新增锚定放置策略的上方、下方、自动、空间不足、负坐标、工作区钳制和不相交测试。
- 设置验证覆盖位置枚举、100–1500 ms 采样间隔、旧 1500 ms 配置兼容和字号边界。
- 设置序列化缺省值兼容旧配置。

### UI/控制器

- 新字幕处于 OCR 或翻译中时，最后译文不被清空。
- 新译文首个非空结果原子替换旧译文。
- 旧代次 OCR/翻译晚到时不显示。
- 新字幕出现时取消旧翻译；旧字幕失败重试被取消。
- 字幕变为空时取消该字幕尚未完成的翻译，保留最后显示译文并拒绝迟到结果。
- 近似重复源文字不重复翻译。
- `NoTranslationNeeded` 使用源字幕作为当前译文。
- 网络失败保留最后译文；新字幕出现后重试对象切换。
- 暂停取消在途工作但保留译文；继续恢复采样。
- 重新选区和停止清空译文。
- token 关闭后拒绝迟到字幕更新。
- 透明模式隐藏背景/卡片元素，字号设置立即生效。
- 紧凑字幕模式启用点击穿透，托盘暂停/继续、重新选择和停止命令只作用于活动字幕会话。

### Windows

- OCR 引擎按语言复用、语言切换释放、服务释放取消排队工作。
- 固定区域捕获不隐藏播放器，也不会因字幕浮层造成 OCR 自反馈。

### 手工测试

- Windows 10 22H2 和 Windows 11 x64。
- YouTube、Netflix 等网页播放器，以及本地 PotPlayer/VLC 的无边框全屏。
- 100%、125%、150%、200% 缩放和双显示器。
- 字幕区域靠近屏幕顶部、底部、左侧和右侧。
- 长句、两行字幕、短句和快速对白。
- 暂停/继续、重新选择、停止、会话锁定和紧急暂停。
- 慢网、断网、认证失败、额度耗尽和免费服务限流。

## 验收标准

- 轮盘和快捷键可以启动字幕翻译并重新选择区域。
- 设置中可选择字幕上方、下方、自动定位，并调整字号。
- 常态字幕显示为无背景纯文字，位置贴合捕获区域且不覆盖字幕。
- 新字幕等待翻译期间持续显示旧译文。
- 新译文首个非空结果出现时立即且原子地替换旧译文。
- 旧 OCR/翻译结果不能覆盖新译文。
- 网络慢时采样和下一句字幕检测不被当前翻译阻塞。
- 停止、重新选区或应用退出后不保留或显示旧字幕。
- Release 构建 0 warnings、0 errors，完整测试通过。
