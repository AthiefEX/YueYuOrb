# QQ / TIM / 微信消息弹幕设计

日期：2026-10-31。状态：方案 2 已选定，本文待用户批准；尚未开始产品实现。

## 目标与范围

在月语悬浮球中显示用户授权接入的 QQ、TIM、微信群聊与私聊消息。支持横向飘过、纵向滚动、会话筛选、私聊优先提醒、图片及自定义外观。保留 WPF 与 Windows 10 22H2 / Windows 11 x64 兼容性。默认关闭，不主动发送聊天消息、不自动操作会话、不要求用户向月语提供聊天账号密码。

## 路线比较与决定

1. 轻量：系统通知及客户端公开的无障碍界面内容；部署改动少，但漏消息、缺少图片和会话身份的情况无法消除。
2. 混合（用户选择）：轻量接入为默认，可选本地消息桥接增强，统一显示和规则引擎。
3. 完整桥接优先：依赖指定第三方适配器，内容可能更完整，但客户端版本、登录与维护依赖更强。

不承诺仅靠系统通知获得完整聊天记录，也不将 QQ 机器人接口视为用户个人账号的全部聊天接口。用户选择了混合架构，但尚未选择或授权安装具体第三方桥接软件。

## 接入验证与交付边界

先实现隔离的接入验证，不把未验证来源标为支持。分别记录 QQ、TIM、微信的实际客户端版本，验证前台、后台、最小化、关闭通知、免打扰时的正文、会话身份、私聊类型、图片、@标记、事件延迟与重复行为。

Windows UserNotificationListener 需要能力声明和用户授权。第一步验证当前非打包 WPF 发布形式及 Windows 10/11；若需要包身份，采用可选、可卸载的签名通知助手承载能力，主程序与便携版仍可独立启动并使用桥接。助手必须另行显式安装，不以便携程序启动为由静默注册。无法获得签名/身份时，通知来源显示不可用，不阻止其他来源。具体助手部署实现由验证结果决定并写入实施计划。

UI Automation 只读取用户选定客户端实际公开的内容，不切换会话、不抢焦点、不扫描历史来伪装实时消息。能力不足时明确降级；不采用持续 OCR 扫屏作为默认后台消息来源。

桥接协议及模拟适配器可以独立交付，但“支持真实 QQ/TIM/微信”必须有相应真实来源验证。实际第三方适配器的选择、许可证、维护状态、版本和登录要求要形成单独评估，不能用通用接口完成冒充全部平台接入完成。若没有可接受适配器，列出未覆盖平台及功能，回到用户确认缩减范围或选择适配器。

## 架构

消息源适配器 → 标准消息 → 身份/能力校验 → 去重 → 会话过滤和提醒规则 → 有界调度队列 → 独立弹幕窗口。

标准消息包含 source、accountId、conversationId、conversationKind、senderId、显示名称、messageId、接收时间、正文片段、图片引用及明确的 mention 标记；缺少字段保留 unknown，不猜测为私聊。身份以来源+账号+稳定会话 ID 区分，同名群不合并。没有稳定 ID 的来源使用明确标示为“通知名称匹配”的规则，不能宣称精准群筛选。无法识别会话的消息默认不显示，可单独允许。

同一账号优先选择一个权威来源；切换源时清空待显示队列。不要默认把轻量和桥接重复输入混合；确需合并时使用稳定消息 ID，缺失 ID 才短时间辅助去重，并容许真实的重复文本消息。

来源状态：未启用、需要授权、连接中、已连接、能力受限、已断开、错误。正文和图片只作短期内存处理，不记录到日志、不上传到月语服务器、不保存历史。账号标识/会话规则可保存，凭据由 Windows 用户级保护存储。

## 本地桥接边界

仅监听 loopback，使用随机令牌认证、协议版本协商、长度/频率限制；不开放局域网访问。断连重试采用退避。收到无效事件拒绝并给出不含正文的诊断。重连默认只接收新消息，拒绝无界历史补发；adapter 需提供 live/history 标记及会话能力。

首版图片走限尺寸的随事件二进制/编码数据，不任意读取客户端传入的文件路径或下载任意 URL；限制压缩体积、解码像素量和格式，解码超时/失败显示 [图片]。第三方媒体下载由用户选择的适配器完成。具体协议编码、端口选择、适配器进程隔离留给实施者。

## 显示与交互

横向：默认右向左，独立轨道与间距控制；同轨同速度，空间足够才放入下一条，避免追尾。纵向：文字正常横排，新消息在底部进入，旧消息向上移并淡出；不是中文竖排文字。

默认无背景、鼠标穿透、不激活窗口。编辑区域时显示边框和拖动/缩放手柄，完成后恢复穿透。位置按显示器和相对工作区保存；断屏回主屏幕并夹紧到可见区域。点击外部不关闭持续弹幕。支持减少动画设置，以静态更新代替持续飘动。

设置页“消息弹幕”：来源连接；群聊多选与私聊名单；横向/纵向；字体/字号/颜色/透明度/描边；速度/间距/停留时间/密度；显示器/位置/区域宽高；昵称/群名开关；图片开关及缩略图上限；提醒规则。使用现有玻璃胶囊样式，含本地模拟消息预览，预览不写入真实队列。

建议默认值（设计建议，非用户指定）：主屏幕右上区域宽 600、高 240 DIP；横向、20 DIP 字体、白色文字+细暗描边、90%不透明度、3 条普通轨道；图片默认关闭。区域过小时降低轨道数，字号和位置始终限制在可用区域内。

## 消息与提醒规则

普通群消息只显示已选择会话。私聊开关独立于群选择；提供“私聊立即显示”选项，默认关闭以避免意外暴露私聊。开启后通过独立提醒轨道/纵向顶部提醒槽直接显示，绕过普通队列，仍服从私聊排除名单、总开关和锁屏暂停。

明确 @我、指定联系人、关键词匹配可以触发高亮、加粗和单独颜色；缺失 @ 元数据时只提供关键词规则，不宣称能准确识别 @。排除名单优先于提醒，私聊优先于普通群规则；同一条仅显示一次，以最高优先级样式呈现。

即时指消息进入月语后的调度，不承诺客户端投递延迟。建议有效新提醒入队后 200ms 内启动显示（不包含外部接收延迟，目标需性能测试）。提醒槽繁忙时替换当前内容并将仍有效消息放入有界提醒队列，不能叠成不可读文本。

建议普通队列上限 100、TTL 30 秒；提醒队列 20、TTL 60 秒。超限丢最旧项，聚合提示略过数量而不保存正文；暂停时停止接收显示，恢复后只显示新消息。启动不重播通知中心旧消息；锁屏、关闭来源、切换账号清空待显示及去重缓存。

## 现有功能集成

轮盘新增“消息弹幕”开关，沿用其他功能按钮布局。快捷键支持总开关、暂停/恢复、清空；默认不占用现有快捷键。

与翻译字幕窗口分离，避免外部点击关闭行为、生命周期和 token 互相干扰。默认避免已知字幕区域；空间不足时遵从用户配置，不移动用户已设字幕。截图/OCR 优先捕获排除，无法验证时使用计数暂停租约临时隐藏；并发捕获结束后最后一个租约才恢复。夜间遮罩下弹幕层次遵从既有悬浮内容策略，设置预览保持可读。独占全屏和受保护桌面不保证显示。

## 验收与实施阶段

阶段 A：接入/部署可行性矩阵，确定平台适配器与通知助手需求；不通过的能力明确记录，不能以模拟数据代替。完整交付目标维持 QQ、TIM、微信三种客户端，不自行缩减。进入完整集成阶段的最低条件为三者均有至少一种用户可接受的真实来源，能够区分群聊/私聊、提供正文和稳定会话身份；图片与明确 @ 标记可按来源能力降级。若任一平台达不到最低条件，只交付验证报告并暂停依赖该来源的集成，不将通用框架或部分平台宣布为功能完成；由用户决定替代来源或调整范围。可独立验证的设计和技术工作不受阻塞。
阶段 B：标准消息、来源能力、过滤/去重/有界调度、配置持久化和桥接认证。
阶段 C：两种显示、预览/编辑区域、提醒、图片、轮盘/快捷键和捕获集成。
阶段 D：真实来源端到端验收，跨显示器/DPI、浅深色、锁屏、重连、刷屏和资源释放；Release 构建与相关回归测试。

验收必须包括：选中群 A 不显示群 B；同名群不混淆；私聊开启后绕过群队列但尊重排除名单；提醒只出现一次；无法获取图片时继续显示后续消息；不抢焦点和鼠标；旧通知不重播；关闭功能清理监听与图片；无消息正文日志；队列上限有效；捕获不识别自身弹幕。最终报告分别标明已验证与未验证的客户端/系统版本。
