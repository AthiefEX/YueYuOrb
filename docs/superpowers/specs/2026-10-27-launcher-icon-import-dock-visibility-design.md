# 快捷应用图标自动识别、拖放导入与应用坞显示开关设计

日期：2026-10-27

状态：已批准（2026-10-27）

## 目标

月语悬浮球的快捷应用需要具备三项用户可感知能力：

1. 在“设置 > 快捷应用”中拖入一个或多个 `.exe`、`.lnk` 文件后，自动识别文件类型、名称和路径，并将其加入快捷应用列表。
2. 快捷应用在设置列表、轮盘按钮和轮盘下方快捷应用栏中显示应用自身图标；读取失败时继续使用现有占位图标。
3. 在“设置 > 轮盘”中增加“显示轮盘下方快捷应用栏”开关，控制轮盘下方应用坞是否显示。

本次保留现有“添加 exe”“添加快捷方式”“添加文件夹”按钮，也保留每个应用现有的“加入轮盘/移出轮盘”行为。

## 为什么要改

当前 `LauncherItem` 只保存名称、类型、路径、参数、工作目录、排序和是否加入轮盘，没有图标信息。设置列表、轮盘和底部应用坞都使用固定的应用占位图形，因此用户无法快速辨认应用。

设置页目前只能通过文件和文件夹选择框添加应用。用户希望像向桌面或资源管理器拖放文件一样，把 `.exe` 或 `.lnk` 直接拖入“快捷应用”页面完成添加。

轮盘下方应用坞目前只在存在“未加入轮盘”的快捷应用时自动出现，没有独立控制项。关闭应用坞后，应用本身和轮盘中的快捷项不能被删除或修改。

## 用户可感知行为

### 拖放添加

- “设置 > 快捷应用”页面显示一个轻量拖放提示区。拖入系统文件时，区域以现有冰蓝玻璃视觉高亮；允许放置时显示复制光标。
- 支持一次拖入多个 `.exe` 和 `.lnk`；扩展名不区分大小写。
- 文件路径按规范化绝对路径去重，比较时不区分大小写。重复项目不会被再次加入。
- `.exe` 以程序文件所在目录作为默认工作目录，类型为 `Exe`。
- `.lnk` 保留快捷方式本身作为启动路径，类型为 `Shortcut`，使用 Windows Shell 启动，从而保留快捷方式内已有的参数、工作目录和启动方式。
- 默认显示名称使用拖入文件去除扩展名后的文件名；用户仍可通过“编辑选中项”改名。名称去除首尾空白，最长 80 个字符。
- 新项目追加到列表末尾，默认不加入轮盘，即 `ShowInWheel = false`，因此会显示在应用坞中。
- 拖放不会立即保存或运行应用。只有用户点击设置页“应用”后才写入设置；启动应用仍由已有的快捷应用启动流程完成。
- 支持部分成功：有效项目加入列表，重复或无效项目在状态栏汇总说明。
- 文件夹、普通文件、网址文件以及无法读取目标的损坏 `.lnk` 不作为快捷应用加入。现有“添加文件夹”按钮继续支持文件夹。

### 应用图标

- 设置列表新增图标列，轮盘快捷应用按钮和轮盘下方应用坞改用应用真实图标。
- 图标从 Windows Shell 获取，不访问互联网，不执行目标程序。
- 导入后应用条目先立即出现在列表中，并暂时显示占位图标；图标在后台提取完成后自动替换，不阻塞设置窗口。
- `.lnk` 优先使用快捷方式自身或系统解析出的自定义图标；`.exe` 使用程序文件图标。
- 已通过“添加文件夹”加入的 `LauncherKind.Folder` 项使用 Windows 文件夹图标；图标失败时同样回退到占位图形。
- 图标以适合高 DPI 的尺寸解码，在 24 DIP、42 DIP 等显示尺寸下保持清晰。
- 图标缺失、快捷方式损坏、Shell 返回空图标或缓存文件损坏时，继续显示现有占位图形，不影响添加、编辑或启动。
- 应用图标更新属于增强行为，不要求实时监听目标程序文件变化。以下时机允许后台检查并刷新：首次添加、编辑路径、应用启动后的后台预热、轮盘重新打开且内存缓存为空。

### 快捷应用栏显示开关

- 在“设置 > 轮盘”的快捷应用说明卡中增加“显示轮盘下方快捷应用栏”开关，默认开启。
- 开关关闭时，即使存在未加入轮盘的应用，也不显示整个底部应用坞和其“添加应用”按钮；轮盘中的快捷应用和内置功能不受影响。
- 开关开启时延续当前规则：只有至少存在一个未加入轮盘的快捷应用时才显示应用坞。
- 保存后无需重启应用，下一次打开或刷新快捷面板即按新设置显示。

## 非目标

- 不支持从开始菜单、UWP/AUMID、Microsoft Store 应用、网址或任意虚拟 Shell 项拖放添加。
- 不扫描开始菜单或自动发现系统已安装应用。
- 不变更快捷方式解析后的目标路径，也不把 `.lnk` 自动转换成 `.exe`。
- 不实现拖放排序、从桌面直接拖入轮盘或拖出删除。
- 不下载在线图标、品牌 Logo 或高清应用素材。
- 不保存图标二进制到导出的设置 JSON。
- 不实现图标变化实时监听。

## 失败条件

- 拖入 `.exe` 或 `.lnk` 后界面卡顿，或需要等待图标提取完成才能看到新增项目。
- 快捷方式被解析成目标程序后启动，导致原快捷方式中的参数、工作目录或启动方式丢失。
- 读取图标失败导致应用无法添加、设置无法保存或轮盘按钮消失。
- 重复拖入同一路径产生重复快捷应用。
- 关闭应用坞开关后仍显示应用坞，或开关误删快捷应用、改变其 `ShowInWheel` 状态。
- 新增设置字段导致旧版设置无法加载，或导入导出设置后开关状态丢失。
- Windows 10 22H2 x64 或 Windows 11 x64 上出现图标错位、黑底、透明通道损坏或明显模糊。

## 当前相关组件

- `LauncherItem`：当前快捷应用数据模型，没有图标字段。
- `SettingsViewModel.Launchers`：设置页快捷应用集合，并参与并发设置合并。
- `SettingsWindow`：现有 exe、快捷方式、文件夹选择按钮和编辑/排序逻辑。
- `QuickPanelWindow.Apply`：将快捷应用拆分为轮盘项和底部应用坞项并创建按钮内容。
- `WindowsAppLauncher`：`.exe` 直接启动，`.lnk` 和文件夹通过 `UseShellExecute = true` 启动。
- `AppDataPaths`：本机应用数据目录，已经提供 assets、日志、WebView2 和笔记数据库路径。
- `SettingsMigrator` 与 `SettingsValidator`：设置反序列化、旧字段补全和保存校验。

## 方案比较

### 方案 A：渲染时即时读取系统图标并仅做内存缓存

每次创建设置列表、轮盘或应用坞按钮时，通过 Windows Shell 读取 `.exe`/`.lnk` 图标。

优点：模型和设置文件不需要图标信息，图标能反映当前系统状态。

缺点：首次打开面板存在 UI 阻塞风险，大量快捷应用时开销明显；目标文件移动或网络路径不可用时更容易闪烁。

### 方案 B：导入期解析 + 本地持久图标缓存

拖入文件时解析并添加条目；图标由后台 Windows Shell 服务提取后写入月语悬浮球本地缓存。设置列表、轮盘和应用坞统一从缓存加载图标，失败时回退占位图。新增全局应用坞显示开关。

优点：打开面板时不执行昂贵的 Shell 工作，图标稳定且适配高 DPI；快捷方式启动语义保持不变；缓存可以损坏回退和清理；对 Windows 10/11 兼容性友好。

缺点：需要新增导入解析、图标缓存、UI 异步呈现和缓存维护逻辑。

采用：**方案 B**。

### 方案 C：持续绑定 Shell 图标并监听目标变化

不持久化图标，由 Shell 名称空间视图持续提供实时图标，并监听目标文件和快捷方式变化。

优点：目标程序更新图标后能实时反映。

缺点：COM、文件监视、网络路径和生命周期管理复杂；更容易引入卡顿、闪烁和难以复现的 Windows 版本差异，不符合本次目标。

决定：不采用。图标刷新按明确时机后台执行，不做持续监听。

## 技术设计

### 设置模型

在 `AppSettings` 中增加初始化属性：

```csharp
public bool ShowLauncherDock { get; init; } = true;
```

该属性不属于主构造参数，因此：

- 旧版 JSON 没有该字段时使用默认值 `true`，保持当前行为。
- 不提升 `SchemaVersion`，不修改已有快捷应用 JSON。
- 导出设置会包含该字段；导入旧设置会自然回退到 `true`。

`SettingsViewModel` 增加对应属性，并在 `From(...)` 与 `BuildCandidate(...)` 中使用现有并发合并规则：

- 用户没有改动时，保留 `latest.ShowLauncherDock`。
- 用户改动时，以设置窗口中的值覆盖。

图标二进制和图标缓存绝对路径不写入 `AppSettings`，避免设置导出携带本机缓存路径或数据。

### 应用条目模型

继续使用 `LauncherItem` 表达可启动目标，不改变其位置参数签名。图标缓存属于运行时资产，不作为快捷应用的可移植配置。

`.lnk` 条目继续保存快捷方式路径，不将解析后的目标路径写回 `Path`。快捷方式解析结果只用于：

- 确认目标存在。
- 读取显示名称或图标来源。
- 计算图标缓存指纹。

启动行为继续沿用 `WindowsAppLauncher.BuildSpec`：`Shortcut` 使用 Shell 启动，`Exe` 使用显式参数和工作目录启动。

### 拖放与文件解析

“设置 > 快捷应用”页面的主内容区设置 `AllowDrop = true`，处理 `DragOver`、`DragLeave` 和 `Drop`。

新增可测试的拖放解析层，输入为 `DataFormats.FileDrop` 中的路径集合，输出添加结果：

```csharp
public sealed record LauncherDropResult(
    IReadOnlyList<LauncherItem> Added,
    IReadOnlyList<string> Duplicates,
    IReadOnlyList<string> Unsupported,
    IReadOnlyList<string> Failed);
```

处理顺序：

1. 过滤空路径，使用 `Path.GetFullPath` 规范化。
2. 只接受现有文件且扩展名为 `.exe` 或 `.lnk`。
3. 与当前 `Launchers` 的规范化路径进行不区分大小写比较。
4. 对 `.lnk` 通过 Windows Shell 只读解析目标；目标不存在时视为失败，不加入列表。
5. 为条目分配新的 `Guid`、追加顺序和默认 `ShowInWheel = false`。

拖放高亮只改变视觉层，不改变应用坞或轮盘的布局。状态栏使用现有 `SaveStatusText` 输出结果，例如“已添加 2 个，跳过 1 个重复项，1 个文件不受支持”。

### Windows Shell 服务

在 `FloatDesk.Windows` 中新增只读的快捷应用解析与图标提取服务，由 App 层注入或创建。职责分离：

- `LauncherShortcutResolver`：解析 `.lnk` 目标、工作目录、参数和图标位置，仅读取元数据，不启动进程。
- `LauncherIconExtractor`：获取适合高 DPI 的图标位图并转换为带透明通道的 PNG 字节。
- `LauncherIconCache`：在 App 层管理内存和磁盘缓存、命中判断、原子写入和失效清理。

实现优先级：

1. 使用 Windows Shell 的图标服务获取 256 px 图标，以保留大图标和快捷方式自定义图标。
2. 如果大图标接口失败，回退到传统 `SHGetFileInfo` 图标。
3. 仍失败时返回无图标结果，由 UI 使用占位图形。

Shell 调用在专用后台 STA worker 上串行或低并发执行，不占用 WPF UI 线程。同一路径或同一条目的重复请求合并，避免轮盘快速开关时堆积任务。

### 图标缓存

`AppDataPaths` 新增：

```csharp
public string LauncherIcons { get; }
```

本机目录为：

```text
%LOCALAPPDATA%\FloatDesk\launcher-icons
```

缓存策略：

- 缓存文件为 PNG，文件名使用不可逆的稳定哈希，不使用用户路径作为文件名。
- 指纹由启动路径、规范化图标来源、来源文件大小和最后写入时间组成。
- 同一快捷应用条目路径、快捷方式时间戳或图标来源没有变化时直接命中缓存。
- 写入先写临时文件再原子替换，避免中途退出留下半个 PNG。
- 图标文件无法解码或为空时删除该缓存并回退到占位图标。
- 应用启动或设置应用后，后台预热当前快捷应用图标；同时清理已不再被任何 `LauncherItem` 引用的缓存文件。
- UI 内存缓存使用已冻结的 WPF 图像对象，可以在不同窗口和动画线程中安全复用。

图标缓存不包含程序内容、快捷方式参数、用户文档或翻译数据，仅包含由 Shell 提供的应用图标 PNG。

### 图标呈现

新增一个 UI 呈现适配层，避免在 `FloatDesk.Core` 中引入 WPF 类型。该层提供：

- 同步或已完成的图标读取，用于已经预热的按钮。
- 异步请求，用于设置列表首次加载和未预热条目。
- 统一占位图形，与现有蓝色圆形应用图标保持视觉一致。
- 加载完成后通过 WPF Dispatcher 更新 `Image.Source`，不重建整个按钮。

设置页 `DataGrid` 新增宽度约 44 px 的图标列；路径列继续使用现有文本编辑器。轮盘按钮的 42 px 图标容器和应用坞的 24 px 图标容器改用同一图标服务。图标使用 `Stretch = Uniform`，不拉伸变形。

### 轮盘和应用坞

`QuickPanelWindow.Apply` 仍按 `LauncherItem.Order` 排序并拆分为：

- `ShowInWheel = true`：加入轮盘。
- `ShowInWheel = false`：进入轮盘下方快捷应用栏。

应用坞可见性改为：

```text
ShowLauncherDock && dockLaunchers.Length > 0
```

关闭应用坞时：

- `LauncherDock.Visibility = Collapsed`。
- 不创建应用坞中的快捷按钮和“添加应用”按钮。
- 不改变任何 `LauncherItem`。
- 轮盘的快捷应用、内置动作、滚动和扇形动画保持原行为。

开关开启且存在应用坞项目时，恢复现有应用坞入场动画和横向滚轮滚动。

### 设置界面

“设置 > 快捷应用”调整：

- 标题说明增加“可将 exe 或快捷方式拖入此页面”。
- 列表上方或表格周围提供明显但不喧宾夺主的拖放提示。
- DataGrid 增加图标列。
- 现有添加、编辑、删除、上移、下移、加入轮盘、移出轮盘按钮全部保留。

“设置 > 轮盘”调整：

- 在现有“快捷应用共用同一个轮盘”卡片内增加开关。
- 文案说明关闭只隐藏轮盘下方快捷应用栏，不删除应用或改变轮盘成员。
- 控件设置 `AutomationProperties.Name="显示轮盘下方快捷应用栏"`。

### 保存、导入与导出

- 拖放和图标加载只修改当前 `SettingsViewModel`，用户点击“应用”后才持久化快捷应用。
- 取消设置窗口时，拖放新增和删除的应用与现有行为一致，不保存。
- 设置导入、导出、重置和验证必须覆盖 `ShowLauncherDock`。
- 图标缓存不参与设置导入、导出或重置；导入后由本机后台重新生成缺失图标。

## Windows 兼容性

- 仅面向 Windows 10 22H2 x64 和 Windows 11 x64；所有 Shell API 均使用这两个版本已有的接口。
- 不依赖第三方图标解析库。
- 路径比较使用 Windows 文件系统语义：规范化绝对路径、不区分大小写。
- 高 DPI 下图标按 DIP 显示，PNG 以较高像素尺寸解码；避免从低分辨率图标强行放大。
- 透明图标必须保留 Alpha 通道，深色和浅色主题下都不出现白色或黑色方块背景。
- 网络路径、已断开映射盘和损坏快捷方式不得导致设置窗口或轮盘崩溃。

## 测试计划

### 自动化测试

- 拖放解析：接受大小写不同的 `.EXE/.LNK`；拒绝文件夹、普通文件和不存在的文件。
- 去重：相同完整路径、大小写不同路径、重复拖入同一批文件只添加一次。
- `.lnk` 解析失败不创建条目；`.exe` 工作目录和 `LauncherKind` 正确。
- 设置模型：旧 JSON 缺少 `ShowLauncherDock` 时为 `true`；用户修改能保存；未修改时保留并发更新值。
- 设置导入导出往返保持开关状态。
- 图标缓存：命中、失效、损坏 PNG 回退、原子写入和孤立缓存清理。
- 图标提取失败时快捷应用仍能添加、编辑和启动。
- 设置 XAML 包含拖放区域、图标列、应用坞开关和自动化名称。
- `QuickPanelWindow` 在开关关闭时隐藏 `LauncherDock`，轮盘快捷项仍存在。
- 开关开启但没有应用坞项目时应用坞仍隐藏。
- 快捷方式启动仍使用 `UseShellExecute = true`，不得因图标解析改写启动路径。

### 手动验证

- 在 Windows 10 22H2 x64 和 Windows 11 x64 上，从桌面和资源管理器拖入 exe、lnk 和多个混合文件。
- 拖入带自定义图标的快捷方式、带参数快捷方式和目标不存在的快捷方式。
- 连续快速打开/关闭轮盘，确认图标加载不卡顿、不闪烁、不重复排队。
- 在 100%、125%、150% 和混合 DPI 多显示器下检查设置列表、轮盘和底部应用坞图标。
- 分别使用浅色、深色和高对比主题检查透明图标与占位图标。
- 关闭应用坞开关后确认应用坞消失；重新开启后无需重启即可恢复。
- 重启应用后确认图标从缓存快速加载，不访问网络。

## 隐私与安全

- 拖放只读取文件路径和 Shell 元数据，不执行文件。
- `.lnk` 解析使用只读方式；应用仍只在用户点击快捷应用按钮时启动。
- 不记录快捷方式参数、目标文档或图标来源路径到日志。
- 图标文件仅保存在本机应用数据目录，不发送到任何翻译服务、网页或远程接口。
- 设置导出不包含图标二进制和本机缓存路径。

## 构建者自行决定

- 图标展示适配层使用自定义控件、附加行为还是轻量视图模型，以最小改动和可测试性为准。
- 图标缓存并发上限、后台预热顺序和缓存清理触发频率。
- 图标获取失败日志只记录通用事件名和条目 ID，不记录完整用户路径。
- 拖放提示区的具体布局和动画，但必须服从现有冰蓝玻璃设计系统。

## 验收标准

- 用户可一次拖入一个或多个 exe/lnk，合法条目自动加入设置列表，重复和无效文件有清晰反馈。

- `.lnk` 启动行为与改动前完全一致。
- 用户可在设置中关闭/开启轮盘下方快捷应用栏，保存后无需重启生效。
- 旧设置可无损加载；新设置保存、导出、导入和重置正常。
